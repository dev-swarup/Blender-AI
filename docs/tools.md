## Conventions

- **needs `<helper>`**: the tool is offered only while that helper add-on is installed and enabled.
- **destructive**: the tool deletes or overwrites data. Each call is still a single undo step.
- **async**: the slow part runs off the main thread, such as image generation, downloads and MCP calls.
- **approval**: the user is asked first when *Ask before running Python* is on.
- **asks the user**: the run pauses until the user answers.
- **sub-agents**: starts specialist agents that work concurrently in the same scene.
- Sub-agents nest up to 2 levels, run 4 at a time and are capped at 16 per request. They do not receive `ask_user` or `undo`.
- Tools from connected MCP servers are named `<server>_<tool>` and are added to every agent. They are not listed here.

### get_capabilities

Report the helper add-ons (Rigify, MPFB, LoopTools, Extra Mesh Objects) and whether each is installed and enabled, whether image generation is configured (and with which model), the connected MCP servers, and the Blender version. Call this before relying on a helper add-on or on image generation.

*No parameters.*

### run_python

*approval*

Run Python inside Blender with full bpy access. Use it whenever it's the better tool: geometry nodes, complex procedural geometry, bulk edits across many objects, drivers with custom expressions, particles, physics settings, custom node trees, or any property no other tool exposes. Prefer one well-structured script over many tiny tool calls, keep it idempotent where you can, and print what you need to verify. Each run is one undo step.

| Parameter | Type | Required | Description |
|---|---|:---:|---|
| `code` | string | yes | Python to run inside Blender with full access, like the Python console. Pre-imported: bpy, bmesh, mathutils (Vector, Matrix, Euler, Quaternion), math, random, numpy as np; C = bpy.context, D = bpy.data. Import anything else you need. print() output is returned; assign to `result` to return a value. |
| `purpose` | string | yes | One short sentence on what the script does (shown to the user). |

### spawn_agents

*sub-agents*

Start specialist sub-agents for self-contained parts of the job. All tasks in one call run at the same time, each with a fresh context and its own tools, in the same Blender scene; the call returns when they are all done, with each agent's report. Roles: model_builder (models and game-map pieces), scene_builder (layout, lighting, camera, environments), animator (rigs, keyframes, cameras, physics), material_generator (materials and textures). A sub-agent knows nothing about this conversation: brief each task completely (what, real size, location, the collection to build in, style, what not to touch).

| Parameter | Type | Required | Description |
|---|---|:---:|---|
| `tasks` | list of object | yes | Tasks to run in parallel. |
